# Porting this build to CodeBuddy (§16, §6.3)

This is what changes, and what doesn't, when moving from this Claude Code MVP to the CodeBuddy submission build. Written now so the port is mechanical, not a redesign.

## What doesn't change

Everything in `src/shared/schemas.py`, `src/shared/config.py`, all agent logic in `src/agents/`, the state machine, guardrails, and pipeline wiring. The prompts, thresholds, and business rules are already correct — porting is not a rewrite.

## What changes, and where

1. **Database** — `src/db/client.py` only. Swap SQLite for Postgres (+ `pgvector` per §3). This file was already isolated for exactly this swap; nothing outside it references SQLite directly.
2. **Model calls** — `src/llm/client.py`. Replace the direct Anthropic API client with CodeBuddy's native model tiers (Fast/Balanced/Primary/Deep), per §16's model-routing table. Do **not** use CodeBuddy's "Configure custom models" to point back at the raw Anthropic API — that bypasses CodeBuddy's own credit usage tracking, which undermines the hackathon's proof-of-usage requirement (flagged in §16 already).
3. **Embeddings for Agent 2** — currently local TF-IDF (`sklearn`), documented in `agent2_duplicate_checker.py` as a demo-scope stand-in. Swap for a real embedding call + `kb_documents`'s vector column once ported — the interface (`find_closest_match`) stays the same, only the similarity computation changes.
4. **Dashboard** — currently static HTML rendered by Python scripts in `dashboard/`, because this build's folder is on a mount that can't hold a live dev server (documented in `render_topline.py`). Port to the Next.js app per §15's repo structure — the HTML/data shape already matches what those components need, this is a reimplementation in React, not a new design. **See TECH-SPEC.md §9.3 for the exact UI/interaction spec** (three-panel layout, the two-column execution graph, the Gate 2 decision flow, the cross-frame messaging protocol) — reproduce that behavior, don't redesign it.
5. **Mock mode** — `src/llm/client.py`'s `MOCK_MODE` flag (active whenever `ANTHROPIC_API_KEY` is unset) should stay in the ported codebase as a test mode, even once real CodeBuddy model calls are wired up — it's what let Phases 1-5 be fully verified here without spending credits, and it's useful for CodeBuddy-side testing too.

## Verification after porting

Every phase has a real test file (`tests/scenarios/`, `tests/eval/`) that passed against this build. Re-run them after each step above — a port that breaks `test_phase1.py` through `test_phase5.py` isn't done, regardless of what the UI looks like.

## Zip contents, when ready

`src/`, `dashboard/`, `data/`, `tests/`, `scripts/`, `TECH-SPEC.md`, `BUILD-TASKS.md`, this file. Leave `pmo_mvp.db` out — it's a local SQLite artifact (see `src/db/client.py`'s comment), regenerated by `scripts/run_demo.py` on the other side, not something to carry over.
