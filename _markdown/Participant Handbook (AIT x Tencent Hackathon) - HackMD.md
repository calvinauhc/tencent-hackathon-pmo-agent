VII. Product FAQs
I. Common Q&A
1. Agent or chatbot?
Both WorkBuddy and CodeBuddy are AI agents, not chatbots. They plan the
steps, operate on your files/code, run multi-step tasks, and hand you a
finished, verifiable result.
2. What model can I use in the free version?
Built-in models organised by capability tier:
CodeBuddy: Fast · Balanced · Primary · Deep (each has a credit multiplier,
e.g. Fast 0.34× → Deep 2.20×).
WorkBuddy: Default · Fast · Balanced · Primary · Deep
You can plug in your own model via "Configure custom models":
how-to guide (CodeBuddy (https://www.codebuddy.ai/docs/cli/models) / WorkBuddy
(https://www.workbuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-
Description/Model))

3. Credits vs. Token? Where can I see the credits consumption process?
Credits are driven by two things: how much the model processes (tokens) and
which model you pick (its rate multiplier) — more tokens or a higher-tier
model means more Credits.
Codebuddy / Workbuddy credits usage site: Tencent Cloud Code Assistant
CodeBuddy – AI Code Editor (https://www.codebuddy.ai/profile/usage)
4. What's the difference between default mode, ask mode and plan
mode?
Default (a.k.a. Craft) — "you say, I do."
The agent takes action immediately: reads/writes files, runs commands,
and delivers the result end-to-end. Best when you just want it done.
Ask — "talk only, hands off."
It answers questions, reads and analyses, but makes no changes — no file
edits, no commands. Best for exploring, reviewing, or Q&A when you're
not ready to let it act.
Plan — "think first, do second."
It analyses your request and lays out a step-by-step plan for you to
review; it only executes after you approve. Best for complex or high-
stakes tasks where you want to see the approach before anything
changes.
5. What does "select folder" / "select workspace" mean?
It's you granting the agent a working directory — the folder it's allowed to
read and operate in. Everything happens inside that authorised folder only,
sandboxed, so it can't touch the rest of your machine.

7. Is my data / code safe? Where is it stored? Will it be used to train the
AI models?
Your data and code are private by default, encrypted, and never used to train
our AI models unless you explicitly opt in.
Your personal data is stored on servers in Singapore. Your actual inputs and
outputs are retained on our side for a maximum of 14 days, while much of
your configuration is stored locally on your own device and never sent to our
servers.
Please note that, in order to generate responses, your inputs may be
processed by third-party LLM providers. We therefore recommend that you
avoid sharing any sensitive personal information in your prompts.

1. What's the difference between "new task" and "assistant" ?
● New Task = a fresh, self-contained work thread scoped to one goal, with its
own clean context. Use it when you start something new and don't want it
mixed with earlier conversations.
● Assistant = your persistent personal agent — the always-there companion

2. What's the difference between "Skills, Experts, Connectors" ?
● Skills = capabilities. Packaged scripts and workflows that let the AI perform
a specific action — generate a PPT, process Excel, control a browser
● Experts = capability + domain expertise. An AI role that thinks with the
methods and judgment of a specific field (e.g., a legal or marketing expert).
Use when you have a focused, single-domain problem.
● Connectors = bridges to external services. They link our product to your
outside apps and data (email, Google Docs, Meeting, TAPD, etc.) via
authorized login, so it can read/write on your behalf.
For Codebuddy:
1. IDE or CLI — which one do I install, and what's the difference?
● CodeBuddy IDE — a full AI-powered editor with a visual interface. Best if
you want to see, click, and build (design-to-code, visual debugging, one-click
deploy). Ideal for product managers, designers, full-stack developers, and
beginners.
● CodeBuddy CLI (Code) — a command-line tool that plugs into your existing
terminal workflow. Best if you live in the terminal and want natural-language-
driven automation (Shell / file / task orchestration). Ideal for DevOps, SREs,
and senior developers.
